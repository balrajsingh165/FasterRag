# internals.md — How the Codebase Implements the Contract

The rest of `docs/` specifies **what the system does** (the contract). This document maps that contract onto **where and how the code does it**, so a maintainer can navigate from any documented behavior to the module that owns it, the test that proves it, and the seam to extend. Read [structure.md](structure.md) first for the layer rule; this file assumes it.

Conventions: paths are relative to `src/fasterrag/`; test paths relative to `tests/`. A behavior with an open task is marked with its `TASK-` id — [todo.md](todo.md) remains the only tracker.

## 1. The one rule that explains the layout

Imports point inward: `api/`+`cli/`+`facade.py` → `services/` → `core/`+`workers/` → `adapters/` interfaces. Vendor types never leave `adapters/`; routers and CLI commands contain no business logic (a router that grows an `if` about retrieval is a bug); `services/` is the only writer of state. The three control surfaces are thin shells over one service layer — which is why REST, CLI, and library behavior cannot diverge, and why a capability is "done" only when all three shells expose it (the gap class TASK-0251 catches).

## 3. Lifecycle traces (follow one request through the files)

**Query (`POST /v1/query`)**: `api/main.py` middleware stack (auth → limits → RED metrics) → `api/query.py` validates via `api/schemas.py` (strict: unknown fields rejected) → `services/querying.py`: embed the query (embedding cache first) → dense + sparse legs in parallel through the adapter → `fusion.rrf` → `cross_encoder` (failure ⇒ `hybrid_only`) → `core/context.py` assembles within budget → `services/generation.py` builds P1, streams or buffers (grounded-or-refuse), resolves citations, grades faithfulness (P3) → response/SSE events → `services/traces.py` persists the full trace (write failure logged, never fails the request) → metrics + OTLP. Every error anywhere on this path exits through `api/problems.py`.

**Ingest (`POST /v1/ingest` / `rag.ingest`)**: `accept()` classifies sources (`typed_source`), journals the job, returns — constant-time regardless of corpus. `run()`: `resolve_sources` stages url/inline bytes (canonical URI ≠ staging path — the seam that keeps dedup alive) → `CpuWorkerPool.tasks_for` builds deterministic tasks → CPU processes parse+chunk (+enrichment on the async side) → `BoundedQueue` (backpressure) → `EmbeddingWorkerPool` batches → `Indexer` upserts + sparse vectors → checkpoints every N docs → failures dead-letter with reason codes → settle, write `index.lock`, invalidate semantic cache, clean staging.

**Startup**: `config/loader.py` — YAML+env merge, schema validation, cross-field rules, missing-env fatality, `_reject_unenforced_settings` (currently: the two cost budgets) — all before any I/O; a process that serves is a process whose config passed.

## 4. Invariants that hold the design together

1. **Deterministic ids** (`core/identity.py`) make every index write a replace, which is what "resume", "retry", and "re-ingest is a no-op" all reduce to.
2. **Atomic control-file writes** (journal, lockfile): write-temp-then-rename, never in-place.
3. **Identity ≠ location** (`DocumentTask.source` vs `.location`): conflating them silently kills dedup — the CRITICAL block on `readable` is the contract.
4. **Verify-before-write** (archive import, restore): nothing mutates until checksums, counts, and referential integrity pass.
5. **One error funnel, one scorer, one service layer**: problems through `api/problems.py`; eval scores through `services/evaluation.py`; behavior through `services/` — each "one" exists so numbers and behavior stay comparable across surfaces.
6. **Metrics declared at import**, never on first event; the only declared-but-unwritten exemptions are pinned by test.
7. **Observability never fails the observed**: trace-store and cache failures degrade, generation grading failing open (a `null` score never withholds an answer).

## 5. Extension recipes (each step names the gate that catches you)

**Add a config key**: `config/schema.py` (+cross-field rule if any) → same key in root `config.yaml` **and** the example block in [config-reference.md](config-reference.md) with type/default/validation (`test_canonical_config.py` + the reference-parity gate fail on drift) → consume it, or add it to `_reject_unenforced_settings` — an accepted-and-ignored key is the defect class TASK-0156 exists to prevent → unit test both directions of validation.

**Add an error code**: `errors.py` `ErrorCode` + `ProblemSpec` (status, slug, retryable) → row in api-reference's table (parity-gated) → raise it where the taxonomy says → assert the problem body in `unit/api/test_problems.py`.

**Add a chunker**: module in `core/chunking/` honoring `TokenCounter` → register in `create_chunker` + the schema's strategy Literal → export in root `chunking.py` → **add it to the Hypothesis invariant suite's strategy list** (the non-negotiable step) → document in architecture §5 + config-reference.

**Add a parser**: module in `core/parsing/` returning `ParsedDocument` with in-bounds offsets and parse flags → register (MIME/extension dispatch in `__init__.py`) → golden-file fixture + snapshot under `unit/core/parsing/` → thresholds go in `options.py`/`parsing.*` config, never module constants (the TASK-0218 lesson).

**Add a vector-DB adapter**: implement the **whole** `base.py` contract (including aliases, `iterate_points`, snapshots — partial adapters break reindex/portability/backup, which is why the surface reviews matter) → register in `factory.py` or ship as a `fasterrag.vectordb` entry point → pass `tests/contract/vectordb.py` unmodified (the definition of conformant) → integration fixture; update integrations.md status row.

**Add an embedding/LLM provider**: subclass the base in `adapters/embeddings|llm/` → wrap every vendor exception into the taxonomy at the boundary (`# CRITICAL:` block pattern in any existing provider) → wire `reliability.timeouts` → factory or entry point → extra in `pyproject.toml` + lazy import + `ConfigError` naming the install command → faked-client unit tests; credential-gated live check is the TASK-0205 pattern.

**Add a CLI command / API endpoint**: parser entry in `cli/parser.py` + thin `cli/commands/` module (or router in `api/`) that only calls a service → cli-reference/api-reference rows (parity + OpenAPI-drift gates enforce) → scope entry in the pinned route→scope table (API) → tests. Wire **both** surfaces or file the asymmetry as a task immediately (TASK-0251 is the cost of not doing so).

**Add a metric**: declare in `observability/metrics.py` at import → write it from the owning module → row in observability §2 → the never-written pin-test will fail until you either write it or (rare, justified) add an exemption.

## 6. Maintainer gotchas (each cost real time once)

The `__main__` guard is load-bearing on Windows/macOS (spawned pool children re-import the entrypoint; fasterRag raises `CHUNK_FAILED` naming this). `pythonpath = ["src", …]` in pyproject exists because the editable install's `.pth` would otherwise make a worktree's tests run `main`'s code (TASK-0248). The sdist must keep `config.yaml` at its root — relocating it breaks the wheel's force-include (comment in pyproject). Commit only with `.venv` on PATH (hooks are `language: system`). httpx fakes for `AsyncClient` must capture the real class before patching (the module attribute *is* the global) and must stream async iterables, not sync ones. Coverage gate scope is deliberate — and platform-sensitive (TASK-0252). `docs/` is ruff-excluded, but the doc gates (`scripts/check_*.py`, `tests/unit/docs/`) are not optional: they are how the documentation stays true, which in this project is a release requirement, not housekeeping.
