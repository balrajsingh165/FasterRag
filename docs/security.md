# security.md — Secrets, Auth, Multi-Tenancy, Supply Chain

## 1. Secrets handling and `.env` policy

- **`config.yaml` never contains secrets.** It drives all behavior; credentials live ONLY in `.env` (or the process environment). Config references secrets exclusively by env-var name: `api_key_env: OPENAI_API_KEY`.
- `.env` is git-ignored; `.env.example` documents every variable with placeholder values.
- Startup validation confirms every referenced env var exists — a missing one is a fatal `ConfigError` that names the variable but **never logs its value**.
- Secret values never appear in logs, traces, problem responses, or the dashboard. Provider keys are redacted to `sk-***` in any diagnostic output.
- Provisioner-generated secrets (Langfuse `NEXTAUTH_SECRET`/`SALT`/`ENCRYPTION_KEY`) are written once to `.env` and never regenerated on re-provision ([observability.md](observability.md)).

### `.env.example` inventory (beta)

| Variable | Used by | Notes |
|---|---|---|
| `FASTERRAG_API_KEY` | API auth (`security.auth`) | Key material for the control plane. |
| `QDRANT_API_KEY` | Qdrant adapter | Sent by the client; the server enforces it via `QDRANT__SERVICE__API_KEY`. |
| `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `COHERE_API_KEY` | Embedding/LLM adapters | Only those actually referenced by config are required. |
| `LANGFUSE_INIT_*`, `NEXTAUTH_SECRET`, `SALT`, `ENCRYPTION_KEY` | Langfuse provisioning | Generated by the provisioner if absent. |

## 2. API authentication

- `security.auth: true` requires `Authorization: Bearer <key>` on every control-plane endpoint (API); the CLI and library read the same key from the environment when pointed at a secured server.
- **Keys carry scopes**: `ingest`, `query`, `collections`, `admin`. Admin endpoints (provisioning, export/import, collection delete) require `admin`.
- **Rate limiting is on by default once auth is enabled** (`security.rate_limit_per_minute`, per key), returning `429` + `Retry-After`.
- Failed auth returns RFC 9457 problems (`AUTH_MISSING`/`AUTH_INVALID`/`AUTH_SCOPE`) with no information about whether a key exists.
- TLS terminates at a reverse proxy in front of the API ([deployment.md](deployment.md)); plain HTTP is acceptable only on loopback/dev.

## 3. Multi-tenancy isolation

- `security.multi_tenancy: true` scopes collections and API keys to tenants; the tenant id arrives via `security.tenant_header` (default `X-Tenant-ID`) and must match the key's tenant.
- **Isolation is enforced at the service layer** (the only writer of state): every collection operation, query, cache entry, trace, and metric is tenant-tagged; cross-tenant access is `TENANT_FORBIDDEN` regardless of endpoint.
- Semantic-cache entries are tenant-scoped — a cache hit can never leak another tenant's answer.
- Per-tenant token budgets (D9, `cost.per_tenant_token_budget`) bound spend per tenant.

## 4. Vector DB security (Qdrant reference)

- Authenticated access via **`QDRANT__SERVICE__API_KEY`** on the server; the client key comes from `.env` (`vector_db.api_key_env`).
- Qdrant ports (6333, 6334) stay on private networks; remote mode should ride TLS or a private link ([deployment.md](deployment.md)).
- Named-volume persistence (mandatory on Windows/WSL) keeps data off ephemeral layers.

## 5. Input hardening

- Input size limits on all endpoints: `security.max_request_mb` (bodies) and `ingestion.max_document_mb` (documents); oversize → `413 PAYLOAD_TOO_LARGE`.
- Uploaded documents are parsed with hardened parsers in worker processes (crash containment: a parser crash dead-letters the document, never kills the API).
- Metadata filter expressions are validated against the collection's schema — no raw query pass-through to backends.

## 6. Supply chain

- **Pinned, hash-locked dependencies** (uv or pip-tools lockfile committed); CI installs only from the lockfile.
- **Secret scanning in CI** (pre-commit + CI job) — a detected credential fails the build.
- **Non-root containers** for every image fasterRag ships or provisions.
- **SBOM generated at each tagged release** and attached to the release artifacts.
- Base images and provisioned tool versions (Qdrant, Langfuse, Grafana) are pinned by tag/digest — no `latest`.
- Dependency update PRs run the full test pyramid plus the eval regression gate before merge.

## 7. Threat-model notes (beta boundaries)

- The dashboard is read-only but displays prompts/responses — deploy it on internal networks and treat access to it as access to corpus content.
- The trace store (D8) persists full prompts/responses locally; retention is bounded by `traces.retention_days` and the store lives inside the deployment's trust boundary.
- fasterRag never sends corpus data anywhere except the providers the operator configured (embeddings/LLM). Local-only stacks (HuggingFace + Ollama + Qdrant) keep all data on-host.
