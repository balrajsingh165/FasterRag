## How to read this file — standing note, added 2026-11-11 (TASK-0370)

**This document is live. Every dated derivation inside it is frozen.** The two halves were never distinguished in writing, and a reader could not tell a claim that has rotted from a claim that was true at the commit it names. The distinction, stated once:

- **Frozen:** §1's 2026-08-10 table, §1.1's 2026-11-08 table, every `> Re-derived …` block, and §§2–7 as they stand under a derivation date. Each is a statement **about the commit it names**, not about today, and is superseded rather than edited — the same contract as a [CHANGELOG](CHANGELOG.md) entry and a ticked [todo.md](todo.md) line. The evidence for the rule is in the document itself: §1.1 says "Scored against `main` at `650943b`", and a derivation that names its commit has already declared itself a snapshot. Rewriting one to match today would destroy the only thing a confidence history is for — showing what the project believed, when, and on what evidence.
- **Live:** this note, the header line above it, and §0 below. These describe today, carry no derivation date, and are corrected in place the moment the tree contradicts them.

Three consequences, so the rule is usable rather than decorative:

1. **Read every sentence below §1 as prefixed by "as of <the derivation's date>".** Where a frozen sentence has since become false, §0 names it. §0 is the only place in this file that is allowed to state what is true *now*.
2. **A stale frozen claim is not a bug; an unlisted stale frozen claim is.** The defect TASK-0370 found was not that §1.1 says "4 of 6 adapters" — that was true at `650943b`, and the Weaviate adapter landed 62 minutes later. The defect was that nothing told a reader to read it that way, and nothing collected the drift anywhere.
3. **`scripts/check_claims.py` scans this file as if it were live, and that stays true.** The gate exempts `docs/CHANGELOG.md` by name and has never exempted this one. Adding an exemption would silence the gate over 196 lines of claims, including §0, which must stay scanned. The cost is accepted and is the same cost the CHANGELOG exemption records in reverse: a denial inside a frozen derivation can fail the gate even when it was true on its date, and the fix is to move the correction into §0, never to edit the frozen text.

**Re-derivation runs on a clean tree, and says so.** Any future re-derivation is performed with `git status --porcelain` empty and records the provenance line from [verification.md](verification.md) tier −1 beside its counts. The 2026-11-08 derivation was run against a tree carrying 29 uncommitted paths from eight concurrent agents, which is why its volatile counts are marked **snapshot** and why its scores had to be pinned to a HEAD the measurements were not actually taken on. Under this rule it would not have been run at that moment. A derivation measured on a dirty tree cannot be compared with the one before it, and a confidence assessment is nothing but a comparison with the one before it. Where a single fact must be checked between derivations, it is read from the committed object (`git show <sha>:<path>`) rather than from the working tree, and the sha is quoted — that is what §0 does below.

## 1. What the score means

"Confidence in the release" is answered for a specific question: **if `v0.1.0-beta.1` were tagged and published today, how confident are we it would be correct, honest, and safe for adopters?** The 62 is held down almost entirely by *unmade decisions and unverified claims*, not by construction quality — which is why the post-checklist number (84) is close, and why nothing on the checklist requires hardware, new subsystems, or research.

**The method, stated once so each derivation can be checked against it**: six dimensions, fixed weights, a score out of 100 per dimension, a weighted sum, and then an explicit adjustment up or down for cross-cutting findings that no single dimension carries — with the adjustment's reasoning written down. ## 5. Risks and edge cases going into a beta

1. **First-run experience**: default config downloads a 2.2 GB reranker (B6) and multi-GB sentence-transformers — an adopter's first `fasterrag query` may look hung. Mitigation exists (TASK-0174's visibility); the default remains undecided.
2. **Windows-vs-Linux behavior**: two shipped defects were Windows-only; the Windows CI leg covers the fast suite only — integration behavior on Windows outside CI's sight.
3. **Single-replica assumptions**: the rate limiter (TASK-0216) and in-process ingestion (TASK-0130) both quietly assume one replica; the docs say so, but a beta adopter scaling replicas gets N× the configured limit and journal-resume-only restart semantics.
4. **Performance expectations**: the name is "fasterRag" and the ledger cannot yet back it. The framing everywhere is goals-not-claims — but the gap between the name and the ledger is a reputational risk the first measured release closes.
5. **License** — resolved 2026-09-13 as Apache-2.0 (ADR-0008); the embed-in-products funnel the docs court is no longer narrowed by copyleft.

**Added 2026-11-08.**

6. **Green CI is not currently a fact about this repository.** The same HEAD is green on push-triggered runs and red on scheduled ones, 21 commits have no completed verdict at all, and nothing reads the Actions API, so the signal a human looks at is the one that passes (TASK-0313). An adopter does not see this; a maintainer deciding to tag does, and must.
7. **Three verification mechanisms were found vacuous in a single week** — the nightly benchmark, the nightly mutation job, and the push-path secret scan. The risk is not those three; it is that all three were *green*, and that the one thing they have in common is that nobody read their output. Any gate whose failure mode is "concludes success while doing nothing" needs the vacuity guard the doc gates already carry, and the beta should not ship advertising automation that does not run.
8. **One shipped chunking strategy is wrong in a way that costs money and ids.** `strategy: layout` emits ~40× the chunks it should (TASK-0307). It is not the default, it is guarded by a strict `xfail`, and it re-ids every corpus when fixed — so an adopter who picks it during the beta and gets the fix afterwards pays for a full reindex.
9. **Milvus is advertised as shipped and has never spoken to a Milvus server.** `integrations.md` is scrupulous about this. Four other documents were not, as of this derivation. An adopter who reads the adapter table and not the notes column will be the first person ever to run it.
