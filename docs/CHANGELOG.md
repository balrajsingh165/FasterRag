# Changelog

All notable changes to fasterRag are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). Entries are reverse-chronological; dates are `YYYY-MM-DD`. Sections used per release: Added / Changed / Deprecated / Removed / Fixed / Security.

- Differentiation and reliability layer (2026-07-29): `differentiators.md` (twelve flagship capabilities D1–D12 with acceptance tests and proof metrics), `reliability.md` (error taxonomy, resilience patterns), `failure-modes.md` (37-row FMEA), `slo.md` (SLIs, TBD-until-measured targets, error budget policy), `disaster-recovery.md` (backup inventory, restore drill, RPO/RTO).
- Architecture Decision Records ADR-0001–ADR-0006 (MADR style).
- `CLAUDE.md` instruction file, single universal task file `docs/todo.md`, detailed `README.md`.
- Adoption guides and build-de-risking specs (2026-07-29): `docs/quickstart.md` (CLI/Python/REST walkthrough), `docs/cookbook.md` (nine composable configuration recipes), `docs/migration-guide.md` (concept mapping from other RAG frameworks, with explicit trade-offs), `docs/troubleshooting.md` (symptom → cause → fix), `docs/data-model.md` (canonical entity schemas, ID scheme, cross-entity invariants), and `docs/prompts.md` (the four LLM call-site contracts P1–P4, with versioning and override rules).
- Repository hardening (2026-07-29): `.gitignore`, `.env.example`, canonical default `config.yaml` (byte-consistent with the config-reference example), GitHub PR/issue templates enforcing the contribution rules, private vulnerability-reporting policy (`.github/SECURITY.md`), `docs/glossary.md` (canonical terminology), `docs/references.md` (external evidence bibliography R1–R14), `docs/archive-format.md` (D11 portability archive spec v1.0.0), and the golden-set JSONL schema in `docs/testing-strategy.md`.
- Build slice S6, in progress — generation (2026-07-30): LLM provider adapters (`fasterrag.adapters.llm`) for OpenAI, Anthropic, Cohere, Ollama, and any OpenAI-compatible endpoint, behind one contract with two call shapes: `complete` returns a whole answer and its usage, `stream` yields text deltas so time-to-first-token stays low. A streamed call cannot report usage until it ends, which is why the SSE contract sends usage as a separate late event. The Anthropic adapter keeps the system prompt as a top-level parameter rather than folding it into the messages, because that is what makes its prompt caching addressable. Adapters classify failures and never retry, so retry policy stays in one place. Plus context assembly (`fasterrag.core.context`), which packs retrieved chunks into the prompt in relevance order until the token budget is spent, so an overrun drops the least relevant material rather than letting a provider silently truncate from the middle. Near-duplicate chunks are dropped before packing, because chunk overlap guarantees neighbouring chunks share text and spending a context window on the same sentences repeatedly is how context rot happens. Every packed chunk yields a citation carrying its source, page, and character span, recorded from what was sent rather than reconstructed from the answer afterwards.
- Build slice S5 — reranking and evaluation (2026-07-30): the retrieval regression gate (`fasterrag.services.regression`, D7), which compares a run against a committed baseline and blocks a drop beyond `eval.recall_tolerance` or `eval.ndcg_tolerance`. A baseline records the embedding model and retrieval-affecting config hash that produced it, and a mismatched one is refused rather than silently compared, because comparing across a model change measures the model rather than the change under test. A missing baseline blocks rather than passing, since a gate that waves through what it cannot check looks like protection while providing none. The cross-encoder reranker (`fasterrag.core.rerank`, public surface `fasterrag.rerank`), which reads query and chunk together over the fused shortlist and truncates to `retrieval.top_k`. A reranker that cannot load or score degrades the response to `hybrid_only` rather than failing the query, the first rung of the degradation ladder (D4). Candidates are only widened to `retrieval.rerank_top_n` when a reranker will actually consume them. The retrieval eval harness (`fasterrag.core.evals`, public surface `fasterrag.evals`) with the golden-set JSONL format shared by the harness, the regression gate, and Autopilot, plus recall@k, MRR, and nDCG@k. Adversarial records are counted separately rather than averaged in as zeroes, because a query the corpus cannot answer has no ground truth to score against and averaging one in would make a system that correctly refuses look worse than one that guesses. Document-level ground truth is honored alongside chunk-level, so a golden set survives re-chunking. Faithfulness is deliberately absent until the generation slice provides its call site.
- Build slice S4 — retrieval (2026-07-30): hybrid retrieval (`fasterrag.services.querying`) running the dense and keyword legs concurrently, both receiving the same pushed-down metadata filter so they search the same subset, and Reciprocal Rank Fusion (`fasterrag.core.retrieval.fusion`, public surface `fasterrag.retrieval`) combining them on ranks rather than scores at the documented k=60. Fusion runs in fasterRag rather than in the backend so `retrieval.rrf_k` and the leg weights are the values that actually apply. Results carry every leg's rank and score, not just the fused number, because the common retrieval question is why a chunk ranked where it did. Verified against a real Qdrant, including that the keyword leg retrieves an exact part number that dense search alone ranks poorly.
- Build slice S3 — ingestion core (2026-07-30): the parsing pipeline (`fasterrag.core.parsing`, public surface `fasterrag.parsing`) covering PDF with table extraction, type-size heading inference and an optional OCR path, plus HTML, Markdown, DOCX, plain text, CSV, and JSON — every format producing one structured `ParsedDocument` whose block offsets index exactly into its text, with committed golden-file snapshots pinning reading order, table structure, heading paths, and metadata. The chunking pipeline (`fasterrag.core.chunking`, public surface `fasterrag.chunking`) with all five configured strategies — fixed, recursive, layout, semantic, and late — sharing one assembler so the five documented invariants hold for every strategy, asserted property-based with Hypothesis. Embedding provider adapters (`fasterrag.adapters.embeddings`) for local sentence-transformers, OpenAI, Cohere, and Ollama behind one contract that separates document and query embedding, reports the model and version that drift detection anchors on, batches per `embeddings.batch_size`, and classifies provider failures without retrying — retry policy stays with the worker pool. The tiered-embedding router routes documents to cheaper or more precise models by metadata, reusing the vector database filter grammar so operators mean the same thing everywhere. The canonical identifier scheme (`fasterrag.core.identity`), including the deterministic document and chunk ids and the retrieval-affecting configuration hash the index lockfile anchors on. Checkpointed ingestion state (`fasterrag.services.journal`): job records written atomically with a checksum and a retained previous copy so a torn write degrades to resuming slightly earlier rather than losing the job, checkpoints at the configured interval, per-collection content-hash deduplication, idempotency-key replay that returns the original job, and a dead-letter queue whose entries carry a machine-readable reason code from the stable error table. The two worker pools (`fasterrag.workers`): a CPU pool that loads, parses, and chunks in worker processes and streams chunks downstream as each document completes, dead-lettering a bad document rather than failing the pass; a bounded queue that makes producers wait inside the pipeline but rejects with `QUEUE_FULL` at the API boundary; and a stateful embedding pool whose model is loaded once and reused across every batch, batching per `embeddings.batch_size`, routing tiered documents to their model, and retrying with exponential backoff and jitter only what a provider said was retryable. The indexer (`fasterrag.workers.indexer`), which closes the ingest chain: each embedded batch becomes one upsert carrying the dense vector, the BM25 sparse vector, and a payload mirroring the `Chunk` entity, so a citation's span and the model drift detection anchors on are written at index time rather than reconstructed later. The `VectorDBAdapter` contract gained optional sparse vectors on `CollectionSpec`, `Point`, and `SearchQuery` per ADR-0007, with the Qdrant adapter switching between the unnamed dense layout and the named dense-plus-sparse layout that hybrid collections require, and the shared contract suite now proves the keyword leg round-trips against a real backend. The ingestion service (`fasterrag.services.ingestion`), which runs both pools concurrently against one bounded queue so parsing and embedding overlap rather than running in phases, checkpoints as documents complete, resumes from the last checkpoint, dead-letters what the embedding pool could not place, and settles each job as completed, partial, or failed. An end-to-end integration test ingests a real corpus into a real Qdrant and retrieves it over both the dense and the keyword leg. The preflight cost estimator (`fasterrag.services.estimation`, D9), which parses and chunks a corpus for real — because token count depends on overlap and enrichment, not on file size — and reports documents, chunks, tokens, and projected embedding cost per provider before anything is embedded. Prices are dated list prices, and a model with no recorded price reports an unknown cost rather than a fabricated one; wall-clock time is deliberately not projected, because embedding throughput has not been measured yet and an unmeasured projection would be a claim without a measurement. The vector database health check is now registered with `/readyz`.
- Build slice S2 — Qdrant adapter and doctor v1 (2026-07-30): vendor-neutral `VectorDBAdapter` contract with its request and result types and a vendor-neutral metadata-filter grammar (`fasterrag.adapters.vectordb.base`); the provider factory, including third-party registration through the `fasterrag.vectordb` entry point, with built-in names taking precedence (`factory`); the Qdrant reference adapter covering the docker, external, and remote modes, both the 6333 and 6334 paths, `prefer_grpc`, API-key auth, deterministic point-id mapping, filter push-down, and translation of every vendor failure into the typed taxonomy (`qdrant`); system-managed Docker provisioning that converges rather than reinstalls, publishes both ports, uses a named volume, and hands the server key to the container by variable name rather than on the command line (`services.provisioning`); `doctor` preflight diagnostics covering Python, disk, memory, GPU, Docker, secrets, per-port reachability, and backend health, each failure carrying a concrete fix (`services.doctor`); and the shared adapter contract suite run against a real Qdrant in every mode, wired into CI.
- Build slice S1 — skeleton (2026-07-29): the first implementation code. Packaging and tooling (`pyproject.toml` with ruff, `mypy --strict`, pytest and coverage config; `.pre-commit-config.yaml`; `.github/workflows/ci.yml` running the blocking gates; `scripts/check_commit_message.py` enforcing the single-line no-trailer commit rule). Typed error taxonomy (`fasterrag.errors`) with the stable error-code table and its RFC 9457 transport metadata. Structured JSON logging with OpenTelemetry-shaped correlation ids (`fasterrag.observability.logging`). Configuration schema and fail-fast loader (`fasterrag.config`) enforcing every key, bound, and cross-field rule in `docs/config-reference.md`, including the presence of referenced environment variables. API application factory with correlation middleware, problem-document exception handlers, and the `/healthz` and `/readyz` endpoints.

### Fixed

- The HuggingFace embedder reads a model's vector size through whichever accessor the installed sentence-transformers exposes. The name changed in 5.x, and the old one still worked while emitting a deprecation warning, so the adapter now spans both rather than pinning a version. Found by running the adapter against a real model for the first time (2026-07-30).

- Qdrant provisioning now sets `QDRANT__SERVICE__GRPC_PORT`, without which Qdrant leaves its gRPC interface disabled and only port 6333 answers — the provisioner was reproducing the very failure recorded in `docs/failure-modes.md` row 15. Caught by the adapter contract suite running in gRPC mode (2026-07-30).
- Vector-database gRPC failures are now classified by status code, so an authentication rejection over gRPC is reported as non-retryable instead of being retried as a transport blip until the circuit breaker opened (2026-07-30).
- The Qdrant adapter now passes `https` explicitly. The Qdrant client switches to TLS on its own as soon as an API key is supplied, so every authenticated call failed with a TLS handshake error against the plain-HTTP listener a container serves by default. Added `vector_db.https` so the transport is chosen rather than inferred (2026-07-30).
- Provisioning now confirms the backend answers an API call before reporting success. An open TCP port is not readiness: a container binds its listener before it can serve, and a transport misconfiguration connects at the socket level and only fails at the first request — so the failure surfaced in whatever ran next instead of in the provisioner (2026-07-30).
- The default `vector_db.docker.image` moved from `qdrant/qdrant:v1.9.0` to `v1.18.1`. The pinned default predated the features the project depends on: the `/points/query` API needs server 1.10 or newer, as do the sparse vectors and native fusion of ADR-0007, and the client reported the old server as version-incompatible (2026-07-30).

### Security

- Documented secrets policy (`.env`-only, env-var-name references), supply-chain requirements (hash-locked deps, secret scanning, non-root containers, SBOM per release).
- Configuration validation never echoes offending input values, and validation failures are raised without chaining the underlying `ValidationError`, so a credential mistakenly pasted into `config.yaml` cannot reach logs or tracebacks (2026-07-29).
- Interactive API documentation (`/docs`, `/redoc`) is not served: it is a web interface capable of driving the RAG, and the control plane is programmatic only (ADR-0005). The machine-readable `/openapi.json` schema is still published (2026-07-29).
- The Qdrant server API key is exported into the provisioning subprocess environment and passed through with `-e NAME`, so the value never appears in `argv`, a process listing, or a log line. Vector-database authentication failures name the environment variable and are never retried (2026-07-30).
