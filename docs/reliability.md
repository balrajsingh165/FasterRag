# reliability.md — Reliability Doctrine & Patterns Catalogue

**A claim without a measurement is a bug.**

That sentence governs this repository: every "fastest," "most reliable," or "best" anywhere in the docs must trace to a [benchmark ledger](benchmarks.md) entry or a passing test, or it must be rewritten as a goal. This file specifies the engineering discipline that makes reliability provable rather than asserted.

## 1. Error taxonomy (typed exception hierarchy)

```text
FasterRagError                      # root; carries code, trace_id, retryable
├── ConfigError                     # invalid config / missing env var (fail-fast at startup)
├── IngestionError
│   ├── ParseError                  # document unparseable → DLQ reason PARSE_FAILED;
│   │                               # still parsing after ingestion.parse_timeout_seconds → PARSE_TIMEOUT
│   ├── ChunkError                  # chunker invariant violated
│   └── EmbedError                  # embedding stage failure
├── RetrievalError                  # dense/BM25 leg, fusion, or rerank failure
├── GenerationError                 # LLM generation failure
├── ProviderError                   # external provider transport/API error; retryable: bool
├── CacheError                      # cache backend failure (system degrades to cache-off)
└── ProvisioningError               # doctor/provisioner failure; carries fix-it hint
```

Rules:

- Every exception carries `code` (stable, identical to the API problem `code` — table in [api-reference.md](api-reference.md)), `trace_id`, and `retryable`.
- **No bare `except`. No silently swallowed exceptions. Anywhere. Ever.** Every caught exception is either handled with a logged correlation/trace id or rethrown.
- *How a handler satisfies "with a logged correlation/trace id":* by logging at all. The JSON formatter in `observability/logging.py` reads the `fasterrag_trace_id` context variable and stamps `trace_id` onto **every** record, so a plain `_logger.warning("…", extra={…})` already carries the correlation id and a handler never needs to thread one in by hand. The rule is therefore about whether the handler says anything, not about how it says it — which is exactly what `scripts/check_error_taxonomy.py` (§5) measures.
- The API surfaces errors as RFC 9457 `application/problem+json` with the stable `code`; the Python package raises the same typed classes (`fasterrag.errors`); the CLI maps them to exit codes.
- Retries act only on `retryable: true` errors; `retryable` is set at the adapter boundary where the semantics are known (e.g. HTTP 429/503 → retryable; 401 → not).

## 2. Resilience patterns (mandatory on every external interaction)

| Pattern | Rule | Config |
|---|---|---|
| **Timeouts** | Explicit, configured timeout on every network/provider call — no unbounded await exists in the codebase. **Status: wired into every adapter.** The suspected violation this row used to carry as open (TASK-0153) was closed as a **mis-read, not a defect**: the apparent hang was the observer's own shell budget, and a single query returned in 10.78 s on the same deployment. `reliability.timeouts.llm_ms` is applied by the adapter at construction. | `reliability.timeouts.*` |
| **Retries** | Exponential backoff + jitter, only on errors flagged `retryable`; attempts bounded. On the embedding path a provider's `Retry-After` is waited out when it is longer than the backoff, capped at `backoff_max_ms`, and a batch refused for its size is halved rather than retried (TASK-0478). | `reliability.retries.*` |
| **Circuit breakers** | One breaker per provider, owned by the service that calls it: **LLM** (`GenerationService`), **embeddings** (`EmbeddingPool`), and **vector DB** (`RetrievalService`). Each is built once per service instance, never per request — a breaker rebuilt per call counts to one forever and can never open. Open after `failure_threshold` consecutive failures; half-open after `reset_timeout_ms`, admitting **exactly one probe** and refusing every other caller with `CIRCUIT_OPEN` until it resolves (TASK-0450). `check()` returns an admission token carrying the state generation it was issued in, and `record_success` / `record_failure` take it back: every state change starts a new generation, so a call admitted before the circuit opened — a late success above all — cannot close a circuit it never tested. A probe that never reports back (its caller was cancelled) holds its slot for at most `reset_timeout_ms`, then the next caller probes instead. Proven by `tests/unit/core/test_breaker.py::test_n_waiters_on_an_open_circuit_admit_exactly_one_probe` and `::test_a_late_success_from_before_the_outage_does_not_close_it`; **state exported as the `fasterrag_circuit_state` metric**. Only **retryable** failures count: a 401 fails identically forever, so counting it would open the breaker, half-open it after the timeout, fail again, and re-open — presenting a permanent misconfiguration as an intermittent outage. **Status: wired for embeddings and the vector DB** — into the embedding pool's retry loop, checked *inside* it so a breaker that opens mid-batch stops the remaining attempts rather than spending the whole retry budget on a provider already known dead, and into the Qdrant and pgvector adapters. **The `llm` breaker is consulted by the generation service** (TASK-0245): an open circuit raises a retryable `CircuitOpenError`, which takes the same extractive fallback a provider failure takes. All three are built eagerly so the metric reports `closed` from startup rather than springing into existence on the first failure. | `reliability.circuit_breaker.*` |
| **Bulkheads** | Ingestion and query paths use separate worker pools and bounded queues, so an ingestion storm can never starve live queries. Structural — not configurable off. | pool sizes under `workers.*` |
| **Idempotency keys** | All mutating API endpoints accept `Idempotency-Key`; replays return the original result and perform no duplicate work. **Status: shipped 2026-11-08 (TASK-0318).** `api/idempotency.py` is ASGI middleware over the `IdempotencyStore` in `services/idempotency.py`, so a mutating router is covered the moment it is mounted rather than when somebody remembers a dependency. Scope is `(tenant, key)` over a fingerprint of method, path, query and body; a replay returns the stored response with `Idempotent-Replayed: true`; a changed request under a live key is `422 IDEMPOTENCY_KEY_REUSED`; a concurrent duplicate loses an `O_EXCL` race and is refused `409 IDEMPOTENCY_IN_PROGRESS` rather than executing. Only 2xx is stored. `/v1/query`, `/v1/retrieve`, `/v1/estimate` and `/v1/replay` are deliberately out of scope — they are `POST` for the body, not for an effect. **Records are files under the journal root, so replay protection spans every worker on one host but not several hosts without shared storage** ([api-reference.md](api-reference.md) §Idempotency) — the store is an abstract interface with one filesystem implementation as of TASK-0357, so a shared backend is a second class rather than a change to any caller, and which one is the open decision. Lifetime, lease and the kill switch come from `reliability.idempotency` (TASK-0356); `enabled` defaults to **true** because the feature starts nothing on its own and defaulting it off would make a published contract false. Record *files* are reclaimed by a pass that runs beside a request, at most once per lease interval per host and under an `O_EXCL` lease so one worker of N does the walk (TASK-0365 ✅ 2026-11-11); before it, lazy key expiry meant a client using a fresh UUID per request — the recommended usage — left a file behind on every call. The `idempotency_key` body field on `POST /v1/ingest` still works and is deprecated for 1.0. | — |
| **Backpressure** | Bounded queues everywhere; overflow returns `429` with `Retry-After` instead of accepting unbounded work. | `workers.queue_depth` |
| **Degradation ladder** | Component loss maps to an explicit degraded mode, never a silent quality drop (D4). **Status: `hybrid_only` (reranker loss) and `extractive` (LLM loss) are implemented and chaos-verified; the `cache_only` rung (vector-DB loss) is not built yet (TASK-0159) — today that failure surfaces as a retryable `RETRIEVAL_FAILED` problem, exactly as the chaos log in [failure-modes.md](failure-modes.md) records.** The rungs are registered in `services/degradation.py`: `_BUILTIN_RUNGS` maps each one to the code that serves it, `_PLANNED_RUNGS` names the specified-and-unbuilt ones, and the ladder dispatches through the mapping, so a new rung is registered in the commit that ships it or it cannot label a response at all (TASK-0394). **Both query surfaces take the same rungs** (TASK-0438): `answer()` and `stream()` are consumers of one pipeline, so a streamed query whose provider fails with a retryable error before the first `token` is sent serves `extractive` — second `meta`, the passages, `citations`, `usage`, `done` — and counts in `fasterrag_degraded_responses_total` exactly as the JSON path does. Past the first `token` nothing sent can be replaced, so the stream ends on `error` without `done` ([api-reference.md](api-reference.md) §Streaming semantics). | `reliability.degradation_ladder` |

## 3. Data safety

- **Atomic file writes** (write-temp-then-rename) for the ingestion journal, `index.lock`, and the index manifest — a crash can never leave a half-written control file. The ingestion journal goes further (TASK-0437, [ADR-0009](adr/ADR-0009-journal-stays-on-files.md)): its temporary files are uniquely named and `fsync`ed before the rename, the directory is `fsync`ed after it where the platform allows (not on Windows), and the live record is replaced rather than moved aside, so no instant exists without one; a crash, torn write or full disk injected between any two of its file operations is tested to leave the old record or the new one.
- The index manifest and alias swap update **transactionally** (D2): the alias points at exactly one complete, eval-validated collection at all times.
- Idempotent, deterministic chunk IDs make index writes replay-safe (exactly-once effects, D3).
- Backups and the restore drill per [disaster-recovery.md](disaster-recovery.md); the drill must actually be executed and ticked in [todo.md](todo.md).

## 4. Testing pyramid

Specified in full in [testing-strategy.md](testing-strategy.md).

**Built and running:** unit (≥ 85% coverage on `core/`, `adapters/`, `workers/`) · property-based chunker invariants (Hypothesis) · golden-file parser tests · testcontainers integration (Qdrant docker + remote modes, and pgvector) · the shared adapter contract suite · the retrieval eval harness · the chaos suite (D12).

**Built but never run** (TASK-0243): the Locust load *generator* landed 2026-11-07 in `tests/load/`, driven by `python -m tests.load.run_load`; it has never been pointed at a fasterRag instance and there is no load number anywhere in this repository — it is a benchmark, not a result, and it grades nothing. k6 was considered and rejected ([testing-strategy.md](testing-strategy.md) §1.7). **Built and asserting since 2026-11-11** (TASK-0243): `tests/load/test_saturation.py` under the `load` marker and `tests/soak/` under `soak`, both outside CI. They assert behaviour and never a time — boundedness, conservation and typed refusal under saturation; no RSS or handle trend over a sampled series, decided by Theil–Sen plus a permutation test rather than by comparing two endpoints (§1.7a, §1.8). **Still not run**: the 24 h soak itself, proven only on a short run here, and every load measurement — both wait on the reference hardware TASK-0084 needs. **Mutation testing landed 2026-11-04** as `scripts/mutation_run.py`, built on CPython's own `ast` rather than mutmut (which refuses to run on Windows) or cosmic-ray (whose parser rejects valid code in this tree); it runs nightly, never on the push path, and reports survivors rather than failing the build on the count alone, because the set contains equivalent mutants — but since 2026-11-11 a **survivor ratchet** (TASK-0382) fails the job when any target survives more mutants than the measured baseline, or leaves a kill the clock or a signal rather than a test produced, so the job can fail again rather than warning forever ([testing-strategy.md](testing-strategy.md) §1.10). Its first measured run covered four of six targets — 134 mutants, 71 killed, 63 survivors (TASK-0300) — but **that run used the runner before TASK-0303 ✅ fixed its isolation**, when tests were re-read live from the working tree on every mutant while those same tests were being edited, so the split is indicative rather than exact and wants re-deriving. The gaps it pointed at are real; the counts are not evidence. `breaker` is re-verified on the fixed runner at 32 of 34 killed. Mutation checking by hand continues alongside it: the runner finds gaps, a reviewer still proves each new test red before it is trusted.

## 5. Static discipline

- Strict typing: mypy (or pyright) strict mode, zero errors.
- Ruff for lint + format.
- Pre-commit hooks enforce lint, format, typing, and the commit-message rule (single line, no trailers).
- Any `# type: ignore` requires an adjacent `# CRITICAL:` justification (consistent with the comment policy — docstrings only, plus `# CRITICAL:` and `# TODO:`/`# BLOCKED:`).
- **The taxonomy rules above are enforced by `scripts/check_error_taxonomy.py`** (landed 2026-11-07), an `ast` gate over `src/fasterrag` **and `scripts/`**. The handler rules read `src/fasterrag` only until 2026-11-09, when they were widened to the gate scripts themselves (TASK-0338) — until then a swallow inside a gate script was invisible to the gate, which is the worst place for one. The widening was measured before it blocked: over `scripts/`'s 14 modules and 19 handlers there are **0 broad catches and 0 `services`/`adapters` paths**, so `swallow-fallback`, `broad-except` and `untyped-raise` are structurally silent there; `swallow` found **1 hit, hand-classified as a false positive** (`mutation_run.py:536` probes whether a textual mutant parses, so `continue` on a `SyntaxError` is the answer, not a swallow) and is therefore ratcheted by path rather than shipped blocking over that file; `swallow-documented` found **2, both false positives**, and both are warnings. **Status: the gate and its tests ship and its ratchet holds exactly that one measured false positive as of 2026-11-09 (TASK-0317 fixed the six real violations it shipped with, rather than annotating them). It runs in the CI quality job alongside the other `check_*` steps and first executed there on 2026-11-11 (run 42972651661, ~1 s on ubuntu-latest); each gate step carries `if: !cancelled()` so a failure earlier in the job cannot leave it reported as `skipped` (TASK-0317, TASK-0383).** Until it existed nothing checked §1 at all: `ruff` catches a bare `except:` (E722) and nothing else, which left the commoner shape — a handler whose whole body is `pass`, `continue`, or `return None` — unchecked for the life of the repository. Four of its rules fail the build and three only warn, and the split is measured rather than asserted:

| Rule | Severity | What it fires on | Measured on `main`, 2026-11-09 (`src/fasterrag` + `scripts/`) |
|---|---|---|---|
| `swallow` | **error** | A handler whose entire body is `pass`/`continue`/`break`/`return`/`return None`/`...`. Exempt: `StopIteration`/`StopAsyncIteration`, and a `pass` arm on a `try`/`except`/`else` (a probe, not a catch). | 0 in `src/`. 1 in `scripts/` (`mutation_run.py:536`), measured 2026-11-09 and hand-classified a false positive, so ratcheted by path rather than blocking. 4 on 2026-11-07, all ratcheted; all four fixed 2026-11-08 (TASK-0317) |
| `unjustified-ignore` | **error** | `# type: ignore` with no `# CRITICAL:` on the same line or in the comment block above it. Read from comment *tokens*, so a mention inside a string never counts. | 0 sites. 2 on 2026-11-07; both removed 2026-11-08 by fixing the types, not by annotating them (TASK-0317) |
| `swallow-fallback` | **error** | A handler whose whole body is `return <expr>` for a substantive `expr`, catching `Exception`/`BaseException`, where `expr` does not mention the caught exception — the `swallow` shape with a fallback value in place of `pass`. **Scoped to a broad catch by measurement, not by taste**: of 34 lone-fallback returns in the tree, 14 return a value built from the exception and 20 do not; of those 20, 13 are predicates or probes where the exception *is* the answer (`_is_ip_address`, `supports_pooling`, `port_is_free`, the `csv.Sniffer` fallback) — 65% false positives at the wider width. At broad-catch width it was 0 false positives of 1. It also suppresses `broad-except` on the same handler, so a blocking verdict never also sits in a warning bucket. | 0 sites. 1 on 2026-11-08 (`tokenizer.py:81`), fixed the same day (TASK-0333) |
| `unreadable` | **error** | A file under a scan root that `ast` cannot parse or `tokenize` cannot read. Every rule above is then silently unenforced on it, so the gate would report it clean because it could not open it — a vacuous pass of the exact kind this gate exists to catch (TASK-0342). A finding rather than a log line, because these gates run in CI where nothing reads a log and only the exit code is read. | 0 sites, of the 394 files under `src/`, `tests/` and `scripts/` (measured 2026-11-09) |
| `swallow-documented` | warning | The same trivial `return None`, but where the function's return annotation already admits `None`. Warns rather than fails because the absence is published — and stays visible because an annotation cannot tell "missing" from "corrupt". | 9 sites: 7 in `src/`, 2 in `scripts/mutation_run.py` (both false positives, both measured 2026-11-09) |
| `broad-except` | warning | `except Exception`/`except BaseException` that rethrows nothing. A broad catch that translates to a typed error is the adapter boundary working as specified, so 15 of the 22 broad catches in the tree are correctly silent. | 7 sites, all in `src/`: `scripts/` holds **no** broad catch at all (measured 2026-11-09) |
| `untyped-raise` | warning | A **builtin** exception raised from a *public* function under `services/` or `adapters/` with no enclosing `try` to translate it. Warns because it resolves names lexically: a factory call or a local subclass is invisible to it by design. | 1 site. It is gated on a `services`/`adapters` path component, so widening the scan to `scripts/` gave it no reach there and never will |

  The gate carries a **ratchet**, not an allowlist: each `(rule, file)` entry records how many known violations that file holds, keyed by **path and never by line**, so the file may shrink but never grow. Raising a number to make a new violation green is the one thing the gate forbids. It holds **one entry**, `swallow:scripts/mutation_run.py: 1`, which is a measured false positive rather than a backlog item — `test_the_real_tree_carries_no_error_severity_finding_beyond_the_ratchet` asserts that every error-severity finding on the real tree is one the ratchet names, so the entry can neither hide a second swallow in that file nor mean *unmeasured*. It also carries a vacuity guard (trap T12): a run in which **any scan root** matches no module, or which parses no `except` handler, or which never puts a lone fallback `return` in front of the `swallow-fallback` matcher, fails rather than reporting a clean tree.

  What it cannot do: it cannot tell a deliberate swallow from a careless one — the remedy for a deliberate one is a one-line log, not an exemption — and it says nothing about whether the problem+json contract holds at runtime. That contract is held by `api/problems.py`, whose catch-all `Exception` handler renders any unclassified failure as `INTERNAL` with a problem body and a trace id, and is covered by the API tests rather than by this gate.

## 6. Security & supply chain

Specified in [security.md](security.md): pinned hash-locked dependencies · secret scanning in CI · API keys with scopes + rate limiting on by default · non-root containers · input size limits on all endpoints · SBOM at each tagged release.

## 7. Observability for reliability

- **RED metrics** (rate, errors, duration) per endpoint.
- Per-stage spans (parse, chunk, embed, retrieve, rerank, generate) correlated by trace id — the id appears in logs, problem responses, and traces.
- Exported gauges: queue depth, DLQ depth, circuit-breaker state, cache hit rate.
- `/healthz` (liveness) is distinct from `/readyz` (dependencies actually checked).
- Full catalogue in [observability.md](observability.md).

## 8. Release reliability

- Risky features (auto-provisioning, autopilot, dashboard) ship behind config flags defaulting to `false`.
- A PR per reviewable change, small fixes direct to `main` (2026-10-28); a tag at every slice boundary (`v0.x.0-sN`); written revert playbook in [deployment.md](deployment.md).
- Error-budget policy in [slo.md](slo.md): when the budget is burning, feature work freezes and reliability tasks take priority in [todo.md](todo.md).
- FMEA in [failure-modes.md](failure-modes.md): every anticipated failure names its detection signal, mitigation, recovery, and the test that proves it.
