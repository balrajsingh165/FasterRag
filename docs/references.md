# references.md — External Evidence Sources

Companion to the [benchmark ledger](benchmarks.md): **internal** claims about fasterRag are backed by ledger entries; **external** claims (literature, vendor documentation) are backed by the sources below. Every externally-sourced statement in this repository should trace to a row here; a sourced claim that can't is a bug ([todo.md](todo.md)). When our own measurements disagree with a source, the ledger wins and the affected defaults are re-examined.

> **Open correction against R3 (TASK-0247).** Identifying the source showed the repository had been citing it for something it does not say: the ~2,500-token cliff is a *retrieved-context budget*, yet several docs described it as a ceiling on `chunking.chunk_size`, and the "~512–1024-token working range" was never a finding of this source at all. Corrected: [config-reference.md](config-reference.md), [scope.md](scope.md), [architecture.md](architecture.md) §5, [glossary.md](glossary.md) ("Context cliff"), [troubleshooting.md](troubleshooting.md), [how-to-use.md](how-to-use.md) §tuning table, and the warning text in `config/loader.py`, which now states the sequence-length rationale for the 1024 threshold instead. Still carrying the old framing and awaiting correction: [failure-modes.md](failure-modes.md) row 5 ("Oversized chunks past the context cliff"), the docstring/bound `chunk_size: Field(ge=64, le=2500)` in `config/schema.py`, and `tests/unit/config/test_loader.py::test_large_chunk_size_warns`, which asserts only the substring "context cliff" and so would pass against either framing. The 2500 bound may well be a reasonable guardrail, but it needs a rationale that does not cite R3.
>
> **Open tension with R3 (overlap).** R3's Table 1 default is **0% overlap** ("No measurable benefit; reduces cost/complexity"); `chunking.overlap` ships at **64**. The shipped default predates this source and rests on no measurement of ours either. Recorded where the default is specified ([config-reference.md](config-reference.md) `chunking.overlap`); whether to change it is a maintainer decision and must be settled with our own eval harness, not by adopting one preprint's default.

## Rules for adding sources

1. A new external claim in any doc adds (or reuses) a row here in the same change.
2. Quote numbers exactly as the source states them; if a source is singular or preliminary (like R3), say so wherever it is cited.
3. Vendor behavior rows (R4–R10) are re-verified when the pinned vendor version changes; stale rows are updated, not silently trusted.
